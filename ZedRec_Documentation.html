1. Project Overview

ZedRec is an AI-powered professional networking and career platform, similar to LinkedIn but with enhanced AI capabilities. It combines social networking, job discovery, learning management (LMS), AI-powered interviews, and career assistance into a unified platform.

Core Features

  • Professional Social Network: User profiles, posts, likes, comments, connections, messaging
  • Job Portal: Job postings, applications, AI job matching, saved jobs
  • Learning Management System (LMS): Courses, quizzes, progress tracking, AI-powered question generation
  • AI Capabilities: Resume analysis, cover letter generation, mock interviews, skill gap analysis
  • Real-time Features: WebSocket-based notifications and messaging

Technology Stack

Backend

  • FastAPI (Python)
  • PostgreSQL (Primary Database)
  • SQLAlchemy ORM
  • JWT Authentication
  • WebSocket (Real-time)

Frontend

  • React 18
  • React Router
  • Axios (HTTP Client)
  • Vite (Build Tool)
  • WebSocket API

AI & External Services

  • OpenAI API
  • LangChain
  • LangGraph
  • Qdrant (Vector DB)

2. System Architecture

2.1 Overall Architecture

The system follows a 3-tier architecture:

  • Presentation Layer: React frontend with component-based UI
  • Application Layer: FastAPI backend with RESTful APIs and WebSocket
  • Data Layer: PostgreSQL for structured data, Qdrant for vector embeddings

2.4 Request Flow

  1. Client Request: React component calls API method from api.js
  2. HTTP Request: Axios sends request with JWT token in Authorization header
  3. FastAPI Router: Route handler receives request
  4. Authentication: get_current_user dependency validates JWT token
  5. Service Layer: Router calls service method with database session
  6. Database Access: Service uses SQLAlchemy ORM to query PostgreSQL
  7. Response: Data serialized and returned as JSON

3. Database Design & Models

3.1 Database Technology

The system uses PostgreSQL as the primary relational database with SQLAlchemy ORM for object-relational mapping. The database connection is managed through connection pooling for optimal performance.

3.2 Core Database Models

User Model (users table)

Field Type Description
uid Integer (PK) Primary key, auto-increment
username String(50) Unique username, indexed
name String(100) Full name
user_email String(150) Unique email, indexed
password_hash Text SHA-256 hashed password with salt
email_verified Boolean Email verification status
description_id Integer (FK) Reference to description table
last_login DateTime Last login timestamp
created_at DateTime Account creation timestamp

Post Model (post table)

Field Type Description
post_id Integer (PK) Primary key
uid Integer (FK) Foreign key to users.uid
post_desc Text Post content/description
media_url Text URL to attached media
media_type String(20) Type of media (image/video)
likes Integer Like count (denormalized)
comments Integer Comment count (denormalized)
is_deleted Boolean Soft delete flag, indexed
created_at DateTime Post creation time, indexed

Connection Model (connections table)

Manages bidirectional connections between users (similar to LinkedIn connections).

  • connection_id (PK): Primary key
  • user1_id (FK): First user in connection
  • user2_id (FK): Second user in connection
  • status: Connection status (pending/accepted)
  • created_at: Connection timestamp

Job Posting Model (job_postings table)

Field Type Description
job_id Integer (PK) Primary key
poster_id Integer (FK) User who posted the job
title String(150) Job title
description Text Job description
company_name String(150) Company name
location String(150) Job location, indexed
job_type String(50) full-time/part-time/contract, indexed
is_remote Boolean Remote work flag, indexed
experience_level String(50) Entry/mid/senior level
salary_min/max Integer Salary range
status String(20) active/closed, indexed

Job Application Model (job_applications table)

  • application_id (PK): Primary key
  • job_id (FK): Reference to job_postings
  • applicant_id (FK): User applying for job
  • cover_letter: Cover letter text
  • status: pending/reviewed/accepted/rejected
  • applied_at: Application timestamp

3.3 LMS Database Models

Course Model (lms_courses table)

  • id (PK): Primary key
  • title: Course title
  • description: Course description
  • category: Course category, indexed
  • difficulty: beginner/intermediate/advanced, indexed
  • lessons: Number of lessons
  • duration: Course duration

Represents sections/lessons within a course. Has order_index for sequencing.

Course Resource Model (lms_course_resources table)

Stores resources (videos, documents, links) associated with courses.

Question Model (lms_questions table)

  • id (PK): Primary key
  • course_id (FK): Associated course
  • section_id (FK): Optional section reference
  • question_text: Question content
  • question_type: multiple_choice/open_ended
  • difficulty: Question difficulty level
  • correct_answer: Correct answer (for multiple choice)

User Course Progress Models

  • lms_user_courses: Tracks user enrollment and overall progress
  • lms_user_section_progress: Tracks progress per section
  • lms_user_answers: Stores user answers to questions
  • lms_user_domain_performance: Performance by domain/category
  • lms_weekly_performance: Weekly learning analytics

LMS Analytics Models

  • lms_dashboard: Aggregated dashboard data (cached)
  • lms_activity: User activity log
  • lms_recommendation: AI-generated course recommendations
  • lms_deadline: User-set learning deadlines
  • lms_certificate: Course completion certificates

3.4 Database Access Patterns

  • ORM-based Access: All database operations use SQLAlchemy ORM models
  • Connection Pooling: Database connections are pooled for efficiency
  • Session Management: FastAPI dependency injection provides database sessions
  • Transactions: Automatic transaction management with commit/rollback
  • Indexes: Strategic indexes on foreign keys, status fields, and timestamps
  • Soft Deletes: Posts use is_deleted flag instead of hard deletion

4. Backend Implementation

4.1 FastAPI Application Setup

The main application is defined in backend/main.py. Key features:

  • Lifespan Events: Startup builds frontend and initializes database; shutdown closes connections
  • CORS Configuration: Configurable CORS origins from environment variables
  • Exception Handlers: Global handlers for HTTP exceptions, validation errors, and uncaught exceptions
  • Static File Serving: Serves React build from frontend/dist
  • Router Registration: All API routers registered with /api prefix

4.2 Authentication & Authorization

JWT Token System

  • Access Tokens: Short-lived tokens (configurable expiry, default ~15 minutes)
  • Refresh Tokens: Long-lived tokens (configurable expiry, default ~7 days)
  • Token Storage: Frontend stores tokens in localStorage
  • Token Refresh: Automatic refresh on 401 errors via Axios interceptor

Password Hashing

Passwords are hashed using SHA-256 with salt. The format is sha256$salt$hash. The system also supports backward compatibility with Werkzeug's pbkdf2 and scrypt formats.

Authentication Flow

  1. User submits credentials (username/email + password)
  2. AuthService.login() validates credentials
  3. Password verified using verify_password()
  4. JWT tokens generated using jose library
  5. Tokens returned to client with user information
  6. Client stores tokens and includes in subsequent requests

Authorization Dependency

The get_current_user dependency in dependencies/auth.py:

  • Extracts JWT token from Authorization header
  • Validates token signature and expiry
  • Retrieves user from database
  • Returns user dict for use in route handlers
  • Raises 401 if token is invalid or expired

4.3 Service Layer Architecture

Business logic is separated into service classes. Each service:

  • Receives database session via dependency injection
  • Uses SQLAlchemy ORM for database operations
  • Implements business rules and validation
  • Returns data as dictionaries (not ORM objects)
  • Handles errors and raises appropriate exceptions

Key Services

  • AuthService: Registration, login, token management
  • UserService: User profile CRUD, search
  • PostService: Post creation, updates, deletion, likes
  • FeedService: Feed generation algorithm (connections' posts)
  • JobService: Job CRUD, applications, search with filters
  • LMSService: Course management, enrollment, progress tracking
  • MessagingService: Direct messaging between users
  • NotificationService: Notification creation and retrieval

4.4 WebSocket Implementation

Real-time features use WebSocket connections managed by websocket/manager.py:

  • ConnectionManager: Tracks active WebSocket connections per user
  • Multi-device Support: Users can have multiple connections (multiple tabs/devices)
  • Message Broadcasting: Send messages to all connections for a user
  • Connection Cleanup: Automatic cleanup of disconnected sockets

WebSocket Endpoints

  • /ws/notifications: Real-time notifications
  • /ws/messaging: Real-time messaging

WebSocket Authentication

WebSocket connections are authenticated using JWT tokens passed as query parameters. The connection handler validates the token before accepting the connection.

4.5 AI Integration - LMS Agent

The LMS_agent.py implements AI-powered question generation using:

  • LangGraph: State machine for question generation workflow
  • Qdrant: Vector database for semantic search of course content
  • OpenAI: GPT models for question generation and embeddings
  • LangChain: LLM orchestration and embeddings

Question Generation Flow

  1. Agent receives course ID, difficulty, and question type
  2. Retrieves relevant course content from Qdrant using semantic search
  3. Builds context from retrieved content
  4. Generates question using OpenAI with context and difficulty
  5. Returns structured question data

4.6 Error Handling

  • Global Exception Handlers: Catch-all handlers ensure CORS headers in error responses
  • HTTP Exceptions: Standardized error responses with status codes
  • Validation Errors: Pydantic validation errors return detailed field errors
  • Service Layer Errors: Services raise ValueError for business logic errors

4.7 Configuration Management

Configuration uses Pydantic Settings loaded from .env file:

  • Database connection parameters
  • JWT secret key and expiry times
  • CORS origins
  • Debug mode
  • Connection pool settings

5. Frontend Implementation

5.1 React Application Structure

The frontend is built with React 18 using functional components and hooks. The application uses:

  • React Router: Client-side routing with protected routes
  • Context API: Global state management (AuthContext)
  • Axios: HTTP client with interceptors for token management
  • WebSocket API: Native WebSocket for real-time features

5.2 Authentication Context

The AuthContext provides:

  • Global authentication state (user, isAuthenticated)
  • Login/logout functions
  • Token refresh logic
  • Automatic token refresh on 401 errors

5.3 API Service Layer

The services/api.js file provides:

  • Axios Instance: Pre-configured with base URL and interceptors
  • Token Management: Automatic token injection in requests
  • Token Refresh: Automatic refresh on 401 errors
  • API Methods: Organized by feature (authAPI, userAPI, postAPI, etc.)
  • WebSocket Classes: NotificationWebSocket and MessagingWebSocket

5.4 Protected Routes

The ProtectedRoute component:

  • Checks authentication status
  • Redirects to login if not authenticated
  • Renders child components if authenticated

5.5 Page Components

  • Feed.jsx: Social feed with posts, likes, comments
  • Network.jsx: User discovery and connection management
  • Jobs.jsx: Job browsing, search, applications
  • LMS.jsx: Course browsing, enrollment, progress tracking
  • Messages.jsx: Direct messaging interface
  • Notifications.jsx: Notification center

5.6 Real-time Features

WebSocket connections are established in page components:

  • NotificationWebSocket: Connects on app load, receives real-time notifications
  • MessagingWebSocket: Connects when Messages page is opened
  • Reconnection Logic: Automatic reconnection with exponential backoff
  • Ping/Pong: Keep-alive mechanism to maintain connections

5.7 Build & Deployment

  • Vite: Fast build tool and dev server
  • Production Build: npm run build creates optimized bundle in dist/
  • Static Serving: FastAPI serves built React app from dist/
  • Environment Variables: VITE_API_URL for API base URL

6. Feature Implementation Details

6.1 Social Networking Features

Post System

  • Post Creation: Users can create text posts with optional media
  • Like System: Toggle likes on posts (denormalized count)
  • Soft Deletes: Posts are soft-deleted (is_deleted flag) for data retention
  • Media Support: Images and videos via media_url and media_type

Feed Generation

The feed algorithm:

  1. Retrieves user's connections
  2. Fetches posts from connected users
  3. Filters out deleted posts
  4. Orders by creation date (newest first)
  5. Supports pagination with cursor-based navigation

Connection System

  • Connection Requests: Users can send connection requests
  • Bidirectional: Connections are bidirectional (user1_id, user2_id)
  • Status Management: pending → accepted workflow
  • Network Discovery: Algorithm suggests users based on mutual connections

6.2 Job Portal Features

Job Posting

  • CRUD Operations: Create, read, update, delete job postings
  • Status Management: active/closed status
  • Rich Metadata: Location, salary range, experience level, job type
  • Remote Filter: Filter by remote work availability

Job Search

Search functionality supports:

  • Text search in title and description
  • Location filtering
  • Job type filtering (full-time/part-time/contract)
  • Remote work filtering
  • Experience level filtering
  • Pagination with limit/offset

Job Applications

  • Application Submission: Users apply with optional cover letter
  • Status Tracking: pending/reviewed/accepted/rejected
  • Applicant Management: Job posters can view and manage applicants
  • Application History: Users can view their application history

Saved Jobs

Users can save/bookmark jobs for later viewing. The system tracks saved jobs in the job_saved table.

6.3 Learning Management System (LMS)

Course Management

  • Course Catalog: Browse courses with filters (category, difficulty)
  • Course Structure: Courses contain sections, resources, and questions
  • Enrollment: Users enroll in courses, creating user_course records
  • Progress Tracking: Tracks overall progress and per-section progress

Question System

  • Question Types: Multiple choice and open-ended questions
  • AI Generation: LMS Agent generates questions from course content
  • Answer Submission: Users submit answers to questions
  • Grading: Automatic grading for multiple choice, manual for open-ended

Analytics & Dashboard

  • Dashboard: Aggregated learning statistics (cached for performance)
  • Weekly Performance: Learning activity over time
  • Domain Performance: Performance breakdown by category/domain
  • Activity Log: Tracks user learning activities
  • Recommendations: AI-generated course recommendations

Certificates

Users receive certificates upon course completion. Certificates have unique numbers and are stored in the lms_certificates table.

6.4 Messaging System

  • Direct Messaging: Users can send messages to each other
  • Real-time Delivery: WebSocket-based real-time message delivery
  • Conversation Management: Organizes messages by recipient
  • Read Status: Tracks read/unread messages

6.5 Notification System

  • Notification Types: Connection requests, likes, comments, job applications, etc.
  • Real-time Delivery: WebSocket delivers notifications instantly
  • Read Status: Tracks read/unread notifications
  • Bulk Operations: Mark all as read functionality

Get current authenticated user information.
